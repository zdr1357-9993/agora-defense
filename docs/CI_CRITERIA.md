# CI 기준 (v0 · 2026-11-20)

이 문서는 "무엇이 통과인가"와 "CI를 어떻게 운영하는가"를 정한다.
기준은 걸리는 일이 생기면 바뀐다. 바꿀 때는 아래 **변경 기록**에 한 줄을 남기고, 최종 결정은 현배가 한다.
에이전트는 이 문서를 고치지 않는다. 고칠 이유가 보이면 worklog 에 제안으로 남긴다.

## 2. 운영 규칙

1. **병합 차단.** `main`, `stage` 는 `build`, `db-security` 가 초록이어야 병합한다 (GitHub branch protection 으로 강제). `develop` 은 열어 둔다.
2. **Failed 와 Blocked.** 둘 다 빨간불이고 둘 다 병합을 막는다. 확인하지 못한 것은 통과가 아니다.
   대신 출력에 `FAIL` / `BLOCKED` 를 구분해 찍는다. Blocked 는 막힌 층(이미지·DNS·설치·포트·클러스터)을 적는다.
3. **flaky.** 자동 재시도는 하지 않는다. 밤마다 반복 실행(E2E `--repeat-each=5`)에서 흔들린 시험은 목록에 올리고, 일주일 안에 고치거나 격리한다.
4. **새 표가 생기는 마이그레이션.** 그 표의 "남의 줄 읽기·쓰기 불가" 시험이 같이 와야 병합한다.
   에이전트는 `tests-proposed/` 에 제안만 하고, 현배가 검토해 게이트 폴더로 옮긴다.
5. **시간 예산.** PR CI 는 10분 안. 넘으면 무거운 시험을 밤 쪽으로 옮긴다.
6. **게이트 폴더.** `e2e/ qa/ k8s/ .github/ scripts/` 와 이 문서는 기능 담당 에이전트가 수정하지 않는다.

## 3. 아직 정하지 않은 것

- 시간당 재화 한도(C1) 수치
- 데이터·메커닉 검사 규칙의 검토 (누가 언제)
- 기능 플래그 규칙: 새 기능은 기본 꺼짐 (Codex 요청서에 먼저 적용, 문서화 전)
